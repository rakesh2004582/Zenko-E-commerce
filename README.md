# Zenko E-Commerce — Backend

Spring Boot 3 + MySQL REST API for the Zenko e-commerce platform (Meesho / Myntra / Amazon style
storefront). Cash on Delivery only — no online payment gateway is integrated.

This backend is **not a standalone demo** — it is the real API the companion
[`hinoria_frontend`](../hinoria_frontend) Next.js app talks to
(see `lib/dataLoader.ts` and `lib/apiClient.ts` on the frontend side). Both repos are meant
to be run together. See [`ARCHITECTURE.md`](./ARCHITECTURE.md) for how the two fit together
and how data flows through the system.

## 3. Configuration (`.env`)

All configuration is environment-variable driven (see `src/main/resources/application.yml`).
`spring-dotenv` automatically loads a `.env` file placed in the project root — no need to
`export` variables manually.

```bash
cp .env.example .env
```

Then edit `.env` and set at minimum:

- `DB_USERNAME` / `DB_PASSWORD` — your local MySQL credentials
- `JWT_SECRET` — any long random string (256-bit minimum)

Every variable is documented inline in [`.env.example`](./.env.example). Nothing in `.env`
is ever read from source control — see §7 (Security notes).

---

## 4. Running it

### Option A — Docker Compose (recommended, zero local MySQL install)

From the **repository root** (one level up, where `docker-compose.yml` lives):

```bash
docker compose up --build
```

This starts MySQL 8, waits for it to be healthy, then builds and starts the backend on
`http://localhost:8080`, and the frontend on `http://localhost:3000`. Tables and seed data
are created automatically on first boot (see §5). No manual SQL step is required.

To run **only** the database + backend:

```bash
docker compose up --build mysql backend
```

### Option B — Run locally with Maven

1. Make sure MySQL is running and reachable with the credentials in your `.env`.
2. Copy and edit the env file as described in §3.
3. Build and run:

   ```bash
   mvn clean install
   mvn spring-boot:run
   ```

   Server starts on `http://localhost:8080`. Database and tables are created automatically
   (`DDL_AUTO=update` by default — Hibernate creates/updates schema on boot). No SQL migration
   step is needed to get started.

### Verifying it's up

- Health check: `GET http://localhost:8080/actuator/health`
- Swagger UI: `http://localhost:8080/swagger-ui.html`
- OpenAPI JSON: `http://localhost:8080/v3/api-docs`

## 5. Database & seed data

There is no separate `.sql` dump to import. The schema is generated by Hibernate
(`ddl-auto`, controlled by `DDL_AUTO` in `.env`) and starter data is seeded programmatically
on first startup by `DataInitializer` (`src/main/java/.../config/DataInitializer.java`):

- an admin user
- the category tree
- a sample product catalog with per-size inventory
- a handful of working promo coupons (`WELCOME10`, `FLAT200`, `SUMMER25`, `FREESHIP`)

**Default admin login (seeded automatically):**

```
email:    admin@henoria.com
password: Admin@123
```

> ⚠️ Change this password immediately in any environment other than local development.

If you need a real, versioned schema/seed export (e.g. for a DBA or CI pipeline instead of
letting Hibernate manage it), see [`db/`](./db) for a generated `schema.sql` and `seed.sql`
you can run manually with `mysql < schema.sql`. These are a convenience snapshot of what
Hibernate + `DataInitializer` already produce at runtime — the application does not depend
on them.

## 6. API surface

### Auth
- `POST /api/auth/register` — customer signup → `{ name, email, password, phone }`
- `POST /api/auth/login` — `{ email, password }` → JWT token
- `POST /api/auth/forgot-password`, `POST /api/auth/reset-password`
- Send the token as `Authorization: Bearer <token>` on all authenticated requests

### Public storefront
- `GET /api/products` — pagination + sorting + filtering + search:
  `search, category, gender, minPrice, maxPrice, rating, sizes, colors, brand,
  sortBy (price_asc|price_desc|rating|newest|discount), page, size`
- `GET /api/products/{slug}`, `GET /api/products/featured|new-arrivals|trending`
- `GET /api/categories`, `GET /api/categories/{slug}`
- `GET /api/reviews/product/{productId}` — paginated reviews + ratings
- `POST /api/reviews` (auth) — submit a review (auto-recalculates product rating)
- `GET/POST /api/cart/**`, `GET/POST /api/wishlist/**` — guest-cart aware via `X-Guest-Id` header
- `POST /api/contact`

### Customer (auth required)
- `POST /api/orders` — place order (COD only; deducts stock; applies coupon if given)
- `GET /api/orders`, `GET /api/orders/{id}`
- `POST /api/orders/{id}/cancel` — restocks items

### Seller
- `POST /api/sellers/apply`, seller dashboard endpoints — see `SellerController`

### Admin (`ROLE_ADMIN` required)
- `POST/PUT/DELETE /api/admin/products` (+ `/{id}`) — full CRUD, `GET` includes inactive products
- `POST/PUT/DELETE /api/admin/categories` (+ `/{id}`)
- `GET /api/admin/orders` (filter by `status`), `PATCH /api/admin/orders/{id}/status`
- `POST/PUT/DELETE /api/admin/coupons` (+ `/{id}`)
- `POST /api/admin/upload/image` — multipart image upload → URL under `/uploads/products/...`
- `GET /api/admin/stats` — dashboard stats
- `GET/PATCH /api/admin/users`, `GET/PATCH /api/admin/sellers`

Full, always-current request/response schemas are in Swagger UI (`/swagger-ui.html`) — that
is the source of truth, not this table.

## 7. Design notes & security

- **Soft deletes** — products/categories are deactivated (`active=false`), never hard-deleted,
  so past orders/reviews referencing them stay intact.
- **Stock** — tracked per size in the `inventory` table; deducted at order placement, restored
  on cancel.
- **Pricing** — `finalPrice` is recalculated automatically from `price` and `discountPercent`
  on every save.
- **Search/filter/sort/pagination** live in `ProductSpecification` + `ProductServiceImpl.search()`.
- **COD flow** — `paymentStatus` stays `PENDING` until an admin marks the order `DELIVERED`
  (auto-flips to `PAID`).
- **Stateless JWT auth** — no server-side sessions; `JwtAuthFilter` validates the bearer token
  on every request; role checks via `hasRole("ADMIN")` on `/api/admin/**`.
- **Secrets** — `.env` is git-ignored (see `.gitignore`). Never commit real values for
  `JWT_SECRET`, `DB_PASSWORD`, or the EmailJS keys. Rotate `JWT_SECRET` and the admin
  password before any non-local deployment.
- **CORS** — allowed origins are configured via `CORS_ALLOWED_ORIGINS`, not hardcoded.

## 9. Troubleshooting

- **`mvn spring-boot:run` fails to connect to MySQL** — check `DB_HOST`/`DB_PORT` in `.env`
  match where MySQL is actually listening (`localhost:3306` for a local install, `mysql:3306`
  for the Docker Compose path).
- **401 on every request** — make sure you're sending `Authorization: Bearer <token>` and that
  the token hasn't expired (`JWT_EXPIRATION_MS`).
- **403 on `/api/admin/**`** — you're authenticated but not with an admin account; log in as
  `admin@henoria.com` or promote a user's role in the database.
- **Uploaded images 404** — confirm `UPLOAD_DIR` exists and is writable, and that you're
  requesting the URL exactly as returned by the upload endpoint.
